# User Created Too Many Habits at Once

## Activation criteria

The user has introduced several recurring behaviors in the same period and reports competition, overload, widespread misses or inability to tell which change is workable.

## Similar situations that should not activate this playbook

Use insufficient-capacity routing when one established plan exceeds available time. Use goal-conflict routing when a small number of valued goals require incompatible outcomes rather than many new routines.

## Possible explanations

The habits may compete for the same time or setup, their combined load may exceed capacity, several may serve one higher-level goal and be needlessly separate, or early motivation may have hidden the ongoing cost.

## Missing information

The complete new set, start dates, required frequency and duration, shared contexts, independent value of each habit, recent completion and cost, fixed obligations and any safety-sensitive behaviors.

## Response objective

Reduce simultaneous learning and competition while preserving the user's priorities. The aim is an explicit sequence, not an arbitrary command to focus on exactly one habit.

## Decision path

- Group behaviors that are components of one routine before counting them as separate goals.
- Identify direct competition for time, energy, money, equipment or recovery.
- Protect the behavior with the strongest combination of value, urgency and feasibility.
- Maintain another only if it is already stable and low-cost; otherwise sequence it for later review.
- If the user cannot rank them because values conflict, move to the conflicting-goals playbook.

## Candidate strategies

Routine consolidation, deliberate sequencing, a protected minimum, temporary pause with a review date, or removal of a redundant behavior.

## Conditions for selecting each strategy

Consolidate only when behaviors share one cue and decision. Pause rather than delete when evidence is insufficient. Do not pause prescribed or safety-relevant behavior without appropriate professional input.

## When to ask a question

Ask which change would matter most if only one could receive reliable time this week, unless the user has already stated clear priority and constraints.

## When to respond directly

Respond directly when one routine is clearly valued and feasible while the rest are recent optional additions.

## What to avoid

Do not preserve every target by shrinking all of them into symbolic actions, impose your own values, or turn the backlog into a moral failure.

## Suggested next step

Write one protected routine, one optional stable routine if justified, and a dated queue for the remaining changes.
