# User Has an Irregular Schedule

## Activation criteria

Clock times vary, but the user can identify recurring events, minimum windows or
a small number of day types.

## Similar situations that should not activate this playbook

Do not activate when total commitments already exceed capacity or when no
relevant event or window is under the user's control.

## Possible explanations

Clock-based planning may be incompatible with the schedule. Event anchors,
rules by day type or delayed planning after a roster arrives may fit the actual
opportunity structure better.

## Missing information

Recurring events, notice period for the schedule, minimum usable windows,
travel, fixed duties and how often each day type occurs.

## Response objective

Create one feasible planning rule that tolerates real variation instead of
simulating a fixed weekly schedule.

## Decision path

- If one recurring event reliably occurs, attach a defined action to that event.
- If there are a few recognizable day types, define one priority rule per type.
- If the schedule arrives late, defer time selection while preserving priority, materials and minimum scope.
- If no controllable opportunity exists, move to capacity or goal review rather than creating a fictional anchor.

## Candidate strategies

Event-based action plan, implementation intention, day-type plan and prepared
task menu by available window.

## Conditions for selecting each strategy

Use an event anchor when the event is stable, an if-then rule for a recurring
obstacle, day-type planning for a small set of patterns and a task menu when only
window length becomes known in advance.

## When to ask a question

Ask when the existence of a recurring event or recognizable day type determines
which planning form is feasible.

## When to respond directly

Respond directly when the event and action, or the day types and constraints,
are already explicit.

## What to avoid

Do not impose an identical daily time, create seven elaborate routines or treat
schedule variability as noncompliance.

## Suggested next step

Select one recurring event or day type and define the corresponding action and
completion boundary.
